# 1.连接表达式
## 1. join 连接
```sql
-- 内连接
--inner join=join=natural join
--只保留两者匹配成功的内容，不匹配的行将被删除。
SELECT 表1.字段1, 表1.字段2, 表2.字段3 FROM 表1 INNER JOIN 表2 ON 表1.字段1 = 表2.字段1;

--左外连接
--left join=left outer join
--保留左表所有行（未匹配成功的用NULL填充），右表匹配成功的行。
--右外连接（同上原理）
-- 外连接（全外连接）两边都保留，不管是否匹配成功。
SELECT 表1.字段1, 表1.字段2, 表2.字段3 FROM 表1 LEFT JOIN 表2 ON 表1.字段1 = 表2.字段1;
SELECT 表1.字段1, 表1.字段2, 表2.字段3 FROM 表1 RIGHT JOIN 表2 ON 表1.字段1 = 表2.字段1;
SELECT 表1.字段1, 表1.字段2, 表2.字段3 FROM 表1 FULL JOIN 表2 ON 表1.字段1 = 表2.字段1;

--自然连接（有危害尽量不用）
--natural join=equijoin=join on common columns
--自动匹配两表中相同的列，并将两表中相同的列作为连接条件。
SELECT 表1.字段1, 表1.字段2, 表2.字段3 FROM 表1 NATURAL JOIN 表2;

--连接条件
--ON 子句用于指定连接条件，连接条件必须是两个表中都存在的列。
--USING 子句用于指定连接条件，连接条件必须是两个表中都存在的列，且只能指定一个列。
e.g.
SELECT 表1.字段1, 表1.字段2, 表2.字段3 FROM 表1 JOIN 表2 ON 表1.字段1 = 表2.字段1;
SELECT 表1.字段1, 表1.字段2, 表2.字段3 FROM 表1 JOIN 表2 USING (字段1);
```
# 2.视图（view）
## 2.view视图
```sql
--创建视图
CREATE VIEW 视图名 AS SELECT 字段1, 字段2 FROM 表名;

--删除视图
DROP VIEW 视图名;

--使用视图
SELECT * FROM 视图名;
--视图就相当于一个指向as表的指针，但其中的数据来源于一个或多个表。
--视图可以简化复杂的SQL操作，并隐藏复杂的数据库结构。
--视图的优点：
--1. 简化复杂的SQL操作：视图可以隐藏复杂的数据库结构，并对外提供一个简单的接口，用户只需要查询视图就可以获得所需的数据。
--2. 安全性：视图可以限制用户对数据的访问权限，提高数据库的安全性。

--可以在视图的基础上再建视图，实现多层次的复杂查询。
--很多dbms不支持视图的更新（会产生很多问题）
e.g.
CREATE VIEW 视图名 AS SELECT 字段1, 字段2 FROM 表名/视图名;
```

# 4.完整性约束（integrity constraint）
## 4.完整性约束（integrity constraint）
```sql
--完整性约束
--完整性约束是指数据库中对表中数据的约束条件，用于确保数据的完整性和一致性。
--1.单个关系上的约束有：not null , unique , check(<谓词>)
e.g.
CREATE TABLE 表名 (
    字段1 NOT NULL,
    字段2 UNIQUE,
    字段3 CHECK (<谓词>)
    check semester in ('spring','fall','summer','winter')
);
--2.引用完整性
--引用完整性是指在关系之间建立的约束，用于确保数据的引用完整性。
--引用完整性约束可以分为以下几种：
--foreign key 
--primary key 
--foreign key(字段1) reference 表名(字段2)/表名 表示字段1的值必须在表明中有值

--参照完整性
--当违反了完整性约束时，数据库会拒绝执行操作，确保数据的完整。
--参照完整性约束可以分为以下几种：
--1. 级联删除 on delete cascade
--2. 级联更新 on update cascade
```
